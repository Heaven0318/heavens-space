# Contact form and owner inbox setup

The public form is in `index.html`; the private-data inbox is at `/owner/`. The inbox page shows a login shell to everyone, but message data is protected by Supabase Auth, table grants, and row-level security. No database or Supabase credentials are included in this repository.

1. Create a Supabase project. Run `supabase/migrations/20260926000000_contact.sql` in the SQL Editor (or apply it with the Supabase CLI). It creates `contact_messages`, `owner_accounts`, the private rate-limit tables, and owner-only RLS policies.
2. In Supabase Auth, disable public signups if this project is only for the owner. Create your owner user in Auth and copy its user UUID. In SQL Editor, run `insert into public.owner_accounts(id) values ('YOUR_AUTH_USER_UUID');`. Only Auth users listed in this table can read, update, or delete messages. Never add visitors to it.
3. Deploy `supabase/functions/submit-message` with JWT verification disabled as specified in `supabase/config.toml` (`supabase functions deploy submit-message --no-verify-jwt`). The endpoint does not trust browser fields, rejects foreign origins, and writes with a server-only Supabase secret key sent only in the `apikey` header. Do not put that key in browser files or a public repository.
4. The function defaults to the portfolio origin (`https://heaven0318.github.io`) and Supabase's server-only service-role key for rate-limit hashing. Supabase hosted Edge Functions provide `SUPABASE_URL` and `SUPABASE_SERVICE_ROLE_KEY`. You may override the origin with `CONTACT_ALLOWED_ORIGIN` and provide a dedicated random `CONTACT_RATE_SECRET`; neither is required for the hosted setup. Never expose service-role or secret API keys in browser code. For local development set `CONTACT_ALLOWED_ORIGIN` to the exact local origin, e.g. `http://127.0.0.1:4173`.
5. Fill in `js/config.js` with the project URL and public anon/publishable key. This browser file is tracked so static hosting can serve it; only public values belong there. `js/config.example.js` and `.env.example` show the required names. The public key is safe in browser code; the service-role key is not. Host `index.html`, assets, and the `/owner/` directory together over HTTPS.

Local smoke checks: submit empty/invalid form fields and verify inline errors; submit valid data and verify a 201 response and a row in `contact_messages`; send the same message again and verify 409; send too quickly and verify 429; block network and verify no success message; sign into `/owner/` and test search, filters, mark read, archive/restore, delete confirmation, refresh, and logout. Test a non-owner Auth user: it must see no messages and the inbox must reject access. Test on narrow and wide screens. If a request fails, inspect Edge Function logs, browser Network, allowed origin, and migration/RLS setup.

Rate limiting is five messages per hour and at least 30 seconds between messages per hashed IP (email fallback when the edge proxy supplies no IP). Identical email/subject/body is blocked for ten minutes. These are spam friction measures, not a CAPTCHA; high-volume abuse may require managed bot protection. Messages are stored in Supabase only; no email notification is configured. The owner inbox loads the newest 500 messages per refresh.
